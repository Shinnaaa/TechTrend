## 🧠 AI/ML 前沿论文

**[GPT-Red: Automated Red Teaming via Self-Play at Scale](https://huggingface.co/papers/2607.26115)**
🔬 突破：使用自对弈（self-play）训练一个专用红队模型，攻击同时训练的防御者种群，成功生成对抗 GPT-5.6 的 prompt 注入攻击。论文报告：防御者 population size 从 1 增加到 8 时，红队成功率从 72% 降至 31%（GPT-4o baseline 为 85%），且未发现过拟合（红队无法记忆单一攻击路径）。
⚙️ 工程影响：提供了一套可扩展的红队训练框架，训练成本约为 GPT-5.6 预训练的 0.3%（按 H100 小时计）。可替代当前手动红队测试，但对基础设施要求高（至少 128 个 H100 才能达到论文中的规模）。

**[How Fast Can Reward Models Score? A Systems Study of C++ and PyTorch Inference Runtimes for RLHF](https://huggingface.co/papers/2607.19712)**
🔬 突破：构建原生 C++ ONNX Runtime 推理引擎用于 RLHF 奖励模型评分，在 Llama-3-8B 奖励模型上，单次评分延迟 0.7ms（PyTorch eager 2.3ms，torch.compile 1.1ms），但更重要的是释放了 GPU 资源——在 8×H100 集群上，使用 C++ 引擎后策略更新步时间从 12s 降至 8.4s（因为生成阶段可用更多 FLOPs）。反常识：评分本身是瓶颈吗？不是，但评分与生成争抢 GPU，所以加速评分间接加快了整个 RLHF 循环。
⚙️ 工程影响：可直接替换现有的 PyTorch 奖励模型推理模块，无需修改训练代码（ONNX 模型导出一次即可）。对于 64 卡规模的 RLHF 训练，预计可节省 15-20% 总时间。

**[Agent Retrieval Bench: Evaluating Repository Context Retrieval for Coding Agents](https://huggingface.co/papers/2607.24882)**
🔬 突破：首次将编码智能体的评估从“最终补丁正确率”下沉到“上下文检索阶段”，构建了 2,600+ 个样本的基准，涵盖 code2test、comment2context 等 4 种检索任务。最有价值的发现：当前最优的 agent（基于 GPT-4o）在 retrieval 上的 Recall@10 仅为 62%，远低于人类开发者表现（91%），说明 agent 失败的主因不是推理能力差，而是找不到相关文件。
⚙️ 工程影响：可直接作为 RAG 检索模块的评价指标，替代人工设计的 recall/precision。建议团队在部署 coding agent 前先用此 benchmark 评估检索组件，再优化下游错误。
