## 🧠 AI/ML 前沿论文

**[To Add Is Machine, To Delete Is Human: Measuring and Mitigating Deletion Avoidance in LLM Code Editing](https://huggingface.co/papers/2607.28887)**
🔬 突破：首次量化了 LLM 代码编辑中的"删除回避"问题——SWE-bench Verified 前五模型对开发者补丁的删除召回率最高仅 71.7%，且即使找到正确文件（92%+），精确删除目标行的成功率不足 52%。29.0% 的补丁存在该问题。
⚙️ 工程影响：现有代码生成评估指标（如 pass@k）完全无法捕捉删除回避，因为测试通过不代表代码库可维护性。需要新的评估维度，且训练数据中应增加"删除操作"的监督信号。

**[MemSFT: Mitigating Alignment Tax with an External Parametric Memory](https://huggingface.co/papers/2607.25614)**
🔬 突破：用外部参数化记忆替代 backbone 参数更新，训练记忆模块模仿非参数检索器在领域数据上的行为，从而在领域专精时避免灾难性遗忘。这直接挑战了"领域适配必须微调 backbone"的假设。
⚙️ 工程影响：领域适配成本从"全量微调"降为"训练一个小记忆模块"，且可插拔——同一 backbone 可挂载多个领域记忆，切换领域无需重新加载模型。对多租户场景的模型服务有直接价值。

**[Zero-Mem: Zero-Token Memory Operations for LLM Agents](https://huggingface.co/papers/2607.29377)**
🔬 突破：证明 agent 的记忆操作（写入、检索）可以完全不需要 LLM 调用和 token 消耗——除最终问答外，所有记忆操作通过编码器计算完成，保留原始交互证据。
⚙️ 工程影响：长会话 agent 的 token 成本中，记忆管理可能占 20-40%——Zero-Mem 将其归零。对 API 成本敏感的生产 agent 系统，这是直接的账单优化手段，但需验证编码器方案在复杂检索场景的召回率。

**[Wnuan: Staged Post-Training for Question Answering over Proprietary Enterprise Knowledge](https://huggingface.co/papers/2608.01862)**
🔬 突破：三阶段后训练（文档构建监督 → 通用数据回放的 SFT → 残差错误的 RL）将 32B 模型在 707 题 WnuanBench 上的可接受答案率从 52.76% 提升到 SFT 后 80.06%、RL 后 91.51%。残差错误采样在 100 次更新协议下优于全池采样。
⚙️ 工程影响：企业知识问答的适配有了可复现的量化路径——从 52% 到 91% 的提升幅度说明"通用模型 + 领域后训练"远优于"直接 RAG 或全量微调"。RL 阶段的残差采样策略值得在自有数据集上复现。
