## 🧠 AI/ML 前沿论文

**[StepGuard: Learning Step-Level Guardrails with Scalable Supervision and Safety-Utility Balancing](https://huggingface.co/papers/2608.24777)**
🔬 突破：将 agent 安全监控从"事后轨迹审计"推进到"执行前步骤级拦截"，StepGen 数据引擎自动生成安全/不安全轨迹对，训练出的 guard 模型可在工具调用前预判风险，相比现有事后审计方案将恶意操作拦截率从约 60% 提升至 92%。
⚙️ 工程影响：为 agent 生产部署提供了一个可插拔的安全层——在工具调用 API 前加一道 guard 模型推理（延迟约 50ms），即可实现步骤级拦截，无需修改 agent 本身的推理逻辑。

**[Rubric-to-Code Credit Assignment for Reinforcement Learning](https://huggingface.co/papers/2608.27906)**
🔬 突破：针对 GRPO 在代码生成任务中"序列级奖励均匀分配"的缺陷，提出按 rubric（评分标准）将奖励分解到具体代码区域（事件处理、DOM 片段、CSS 选择器），实验显示在 Web 应用生成任务上比标准 GRPO 的通过率提升约 18%。
⚙️ 工程影响：任何用 RL 训练代码生成模型（尤其是前端生成）的团队，可直接将 RCCA 的奖励分解策略接入现有 GRPO 训练管线，无需更换基础模型。

**[LMSM: LLM Security Framework Inspired by Linux Security Modules](https://huggingface.co/papers/2608.25697)**
🔬 突破：将 Linux 安全模块（LSM）的钩子机制移植到 LLM 推理链路，把可解释性信号（如注意力模式、激活值）标准化为安全控制点，使新增防御手段无需为每个信号单独写校准和策略代码——集成成本从"每个信号 2-3 天"降至"配置一个钩子 30 分钟"。
⚙️ 工程影响：为 LLM 安全部署提供了一个统一框架，类似 LSM 之于 Linux 内核——安全团队可以像写 SELinux 策略一样配置 LLM 的安全钩子，而非为每个攻击向量定制补丁。

## ⚡ 技术范式变化信号

**[MCP 从"协议"演变为"agent 硬件抽象层"**]：devspace、mobile-mcp 等项目的密集出现表明，MCP 正在从工具连接协议升级为 agent 的"设备驱动层"——统一了桌面、移动端、浏览器的操作接口。对工程决策的影响：新 agent 项目应默认基于 MCP 构建工具层，而非自研 API，否则将失去跨模型、跨设备的可移植性。

**[RL 训练从"通用框架"走向"单机型深度优化"**]：microduck_rl 的爆发（+168 star）与 Isaac Lab 等通用框架形成对比，说明低成本硬件（<500 美元）的 RL 训练需求正在催生"一机一环境"的垂直方案。对工程决策的影响：机器人 RL 项目应评估"通用框架 + 自研环境"与"垂直框架"的成本差异，后者在 sim-to-real 迁移成功率上可能高 20-30%。

**[LLM 安全从"事后审计"转向"执行前拦截"**]：StepGuard 和 LMSM 两篇论文同日出现，标志 LLM agent 安全从"检测攻击"转向"预防攻击"——步骤级 guard 模型和 LSM 式钩子机制正在成为标准实践。对工程决策的影响：生产环境部署 agent 时，应在工具调用层预留 guard 模型推理点（延迟预算 <100ms），而非事后分析日志。
