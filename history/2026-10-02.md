## 📌 今日要闻

**1. Cloudflare 开源决策模型 Clef，同时放出 RL 微调平台，HN 456 赞**
决策模型（输出校准概率而非文本）从 9-26 的 Jev 论文、Ollaya 一路走到今天 AWS Strands Decider 2B 和 Cloudflare Clef 同日发布——一周内三家云厂商入场，说明"分类/判断"正在从生成式 judge 里被拆出来单独卖。Clef 是 open-weight，意味着你可以自托管一个专门做路由/审核/风险打分的模型，不用再拿 70B 生成模型跑单 token 分类。 · [Cloudflare Blog](https://blog.cloudflare.com/clef-decision-models/) / [HN](https://blog.cloudflare.com/clef-decision-models/) / [TechCrunch](https://techcrunch.com/2026/10/01/amazon-releases-its-own-jev-clone-as-decision-models-flood-the-web/)

**2. 18 条 RAG pipeline 在 Google FRAMES 上被一个 agent loop 打成 78.9% vs 92.7%**
这是本周对 RAG 工程决策冲击最大的一个数字：精心调优的检索管线（重排、混合检索、chunk 策略）最好成绩落后朴素 agent loop 近 14 个点。FRAMES 是多跳事实推理基准，说明在需要跨文档串联的任务上，"检索一次再生成"的架构本身是瓶颈，不是检索质量。 · [Reddit](https://www.reddit.com/r/LocalLLaMA/comments/1wv0lww/we_benchmarked_18_rag_pipelines_against_an_agent/)

**3. 内存短缺将持续到 2028 年，2027 年合约价"远高于 2026"**
Micron CEO 的原话是 2027 年报价比 2026 年高得多。对工程决策的直接影响：自建推理集群的 TCO 模型要重算——如果你们在做 3 年折旧的 GPU 节点采购，显存成本这一项现在必须按涨价曲线而不是历史均价估。 · [Ars Technica](https://arstechnica.com/information-technology/2026/10/memory-supplies-are-only-getting-tighter-micron-ceo-says/)

**4. Git 3.0 默认切 SHA-256 引发 HN 261 评论争议，反对者称"代价高昂的错误"**
争议核心不是哈希强度，而是 SHA-256 对象 ID 从 20 字节变 32 字节后，所有依赖固定长度 OID 的周边工具（GitHub API、CI 缓存键、monorepo 工具链）都要改。如果你们有自研的 Git 工具或缓存层，现在该去查一遍有没有硬编码 40 位 hex 长度假设。 · [GitButler Blog](https://blog.gitbutler.com/git-3-sha-256) / [HN](https://blog.gitbutler.com/git-3-sha-256)

**5. Tavus 发布 Griffin"Human Interaction Model"，48% 受试者一分钟通话后认不出是 AI**
实时视频通话里处理面部表情、语调、手势，48% 的误认率意味着视频身份验证（KYC 远程面签、面试）的假设已经失效。做远程身份核验的团队需要把"活体检测"升级为"行为一致性检测"。 · [The Decoder](https://the-decoder.com/nearly-half-of-test-subjects-mistook-tavus-ai-video-avatar-for-a-real-person-on-a-one-minute-call/)

## ⚡ 趋势信号

**决策模型一周内从论文变成三家云厂商的产品线**：9-26 Jev 论文 + Ollaya，9-29 OpenAI Decisions API，10-01 AWS Strands Decider 2B + Cloudflare Clef。信号从"新品类出现"变成"品类已成型"——现在的问题不是要不要用，而是选哪家、以及你们的审核/路由逻辑要不要从 prompt 里搬出来。直接影响：内容审核、请求路由、风险打分这三类场景，继续用生成式模型是纯浪费延迟和成本。

**RAG 与 agent loop 的架构之争有了第一个公开基准数字**：78.9% vs 92.7% 的差距足够大到不能再用"看场景"搪塞。延续 9-28 的"harness matters"线索——瓶颈在检索-生成的单次往返结构，不在检索器本身。直接影响：如果你们的多跳问答还在调 chunk size 和 reranker，先花一天搭个最简 agent loop 做对照，可能直接省掉整条管线。

- **[FlexRouter: Learning Complementary Model Sets for Flexible LLM Routing](https://huggingface.co/papers/2609.38585)**：现有 router 独立打分选 top-k，会选中共享失败模式的冗余模型；FlexRouter 显式建模模型互补性，优化"至少一个选中模型答对"的概率——直接对应你们多模型 ensemble 的选型逻辑
