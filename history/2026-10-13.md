issue #48195 指出 `codex` 安装即写入一个持久化、自更新的 daemon，用户没有 opt-in 环节。对在 CI runner、容器镜像、共享开发机上装 Codex CLI 的团队，这是供应链面新增的一个常驻进程——需要确认它在无网络环境下的行为、以及镜像构建时是否会被打进层。 · [GitHub](https://github.com/openai/codex/issues/48195)

**3. 欧洲超市冷柜被批量激活自动除霜，717 条评论，攻击面是未认证的 IoT 控制协议**

**4. Microsoft 研究：清空 agent 聊天历史但保留工作区，解题率最高提升 66%**
"Fork-and-Flush" 针对的是 agent 在长上下文里陷入局部解（"idea basins"）出不来的问题——上下文越长，模型越倾向于在已有思路上微调而不是换方向。这是对"上下文越长越好"的直接反证：正在做长会话 agent 的团队，该把"定期 fork 出新上下文、只带工作区状态"做成可配置项，而不是无脑堆 context window。 · [The Decoder](https://the-decoder.com/clearing-chat-history-helps-ai-agents-find-better-solutions/)

**5. Microsoft 计划 2027 年把自研 Maia 芯片做成 Azure 主力推理系统，Maia 300 每兆瓦 token 数比主流 GPU 高 40%**
Nadella 称其为"最大的赌注"。40% 的每兆瓦 token 优势如果成立，意味着 Azure 上的推理定价有独立于 Nvidia 的下行空间；正在做多年云成本模型的团队，把"推理单价随 Maia 铺开下降"作为一个情景写进预算，而不是假设 GPU 价格曲线。 · [The Decoder](https://the-decoder.com/microsoft-plans-to-scale-its-own-maia-ai-chips-to-gigawatt-levels-by-2027/)

## ⚡ 趋势信号

**"上下文越长越好"正在被两条独立证据推翻**：Microsoft 的 Fork-and-Flush 显示长上下文让 agent 卡在局部解（+66% 靠清历史），billion-context 这类项目则转向"压缩而非扩容"（100K 窗口 + 5 倍 token 节省）。做 agent 架构的团队，本周该把 context 管理从"调大窗口"改成"主动丢弃 + 状态外置"。
> 延续 10-12 的多 agent 成本信号：Vals AI 测出多 agent 贵 5.1 倍但质量提升落在噪声区间，今天的 Fork-and-Flush 是同一方向——上下文和角色数量都在被证明是成本项而非能力项。

**Meta 用"成本换能力"进入前沿档，与 Haiku 5.5 的降价路线正面相反**：Haiku 5.5 把 GUI 操作从 15.7% 拉到 72.4% 同时降价，Muse Wonder 则是基准进前三但单任务成本涨 3 倍。模型选型开始分成两派——按能力上限选，还是按单位任务成本选；agent 产品该按后者做默认，前者只留给确实需要前沿能力的环节。
> 延续 10-08 的 Haiku 5.5 价格战信号：一边降价一边涨价，说明"前沿"和"可部署"正在变成两个不同的采购决策。
