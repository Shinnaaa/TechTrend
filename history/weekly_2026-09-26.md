# 技术趋势周报 · 2026-09-25 ~ 2026-09-26

## 🔭 本周最强信号（Top 3）

**1. Agent Harness 层正在被标准化，且速度超预期。**
strands-agents/harness-sdk 以 8,279 星基数持续增长，意味着上下文管理、工具重试、截断策略这些"脏活"已从各家自研走向公共 SDK。这是 agent 工程从手工作坊进入工业化的标志性事件——未来 6 个月，自研 harness 的团队将面临"维护成本 vs 迁移成本"的正面抉择。

**2. 多 Agent 协作从概念进入"缝合现实"。**
openrig 把 Claude Code 和 Codex 塞进同一 harness，本质是用文本摘要做跨 agent 状态传递。这暴露了当前多 agent 的核心瓶颈：**没有结构化 state 协议**。谁能定义跨 agent 的 state schema，谁就掌握下一层基础设施的入口。

**3. Agent 可观测性成为独立需求。**
starnet 的像素风可视化 +93/天，说明"看得见 agent 在干什么"不再是 nice-to-have。但展示层不等于调试层——真正的分水岭是是否暴露 tool call 原始 payload。这个需求正在从 IDE 插件、harness SDK、独立工具三个方向同时涌入。

## 📈 持续强化的趋势

- **Agent 编排运行时收敛为单二进制/单进程**：google/ax 用 Go 单二进制做编排，反映行业对"编排层不应引入额外运维复杂度"的共识。跨进程 tool 调用的序列化成本，正在取代调度算法成为真正的性能战场。

- **工具注册与路由层独立成组件**：treg 等项目的出现，说明 tool 的注册、路由、幂等性管理已复杂到需要专门抽象。这与 harness SDK 的标准化是同一趋势的两面。

- **本地优先 + 自带 key 的 agent 桌面端**：starnet 代表的"本地 harness + 用户自持凭证"模式在持续获得关注，反映企业对 agent 数据外流的真实焦虑。

## 🆕 本周新冒头的苗头

- **跨 CLI agent 的互操作层**：openrig 是首个把两个主流 CLI agent 做上下文共享的尝试。虽然当前靠文本摘要、信息损耗不可控，但"agent 间协议"这个方向首次有了可跑通的实现，值得盯住它是否演化出结构化 state 传递。

- **Agent 执行过程的可视化调试**：starnet 的像素风只是表象，背后是"agent trace 可视化"这一尚未被大厂产品化的空白。若下周出现暴露原始 payload 的同类项目，这个赛道会快速升温。

## ⚠️ 值得警惕的反向信号

**Google 系 agent 项目的持续性存疑。** google/ax 单日 +1,373 星亮眼，但 Google 的 agent 项目历史上多次一年内停更。在确认有外部 contributor 之前，不建议将其纳入生产依赖——高星不等于高存活率，这是过去三年反复验证的教训。

## 🗓️ 下周关注重点

1. **harness-sdk 的重试/截断策略细节**：重点验证幂等工具失败时是否重复执行，这直接决定能否替换自研 harness。
2. **openrig 是否引入结构化 state 传递**：若两周内仍停留在文本摘要，多 agent 协作的实用价值将被证伪。
3. **starnet 及同类项目是否暴露 tool call 原始 payload**：这是区分"演示玩具"与"生产工具"的唯一硬指标。
